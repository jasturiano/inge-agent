# Generic harness adapter

This is a manual integration contract, not an automatically installed plugin.
Add a short pointer to the resolved BOOTSTRAP.md in the harness's supported global
instructions, or explicitly ask the current session to read it. SOUL.md has no
special discovery semantics. Establish the target repository independently.

Trust the framework explicitly; never silently substitute a repository-local kit.
Enforce a deny-by-default tool profile using the harness's actual capabilities,
including custom tools and egress. Read-only roles must have no executable shell or
mutation tools, not merely a prose prohibition. Gate authorized writer execution
and disable automatic approval. If equivalent enforcement is unavailable, disclose
the gap and restrict work to safe supported operations; do not claim adapter parity.

Git mutations are human-operated except explicitly approved stash push/pop under
WORKFLOW.md. Apply native rules denying other Git metadata writes and mutating
Git/hosting tools; suggest those commands only. If arbitrary execution remains
available, disclose that prompt/tool rules are not filesystem isolation. Never run
code/tests performing other Git mutations or widening the stash exception.

Discover actual file-read/edit/execute tools, skill catalog, model identity and
selection, delegation, approval controls, and session persistence. Record unknowns
as unknowns. Read only relevant capabilities; no credential/configuration dumps.

Default to the current model and a single session. Use specialist roles as reasoning
responsibilities; dispatch only when the harness supports it, it is useful, and
the user/harness permits it. If direct edits are allowed, the coordinator can perform
authorized changes itself. If it is read-only and cannot delegate writes, return
the concrete blocker and proposed change; do not seek a shell bypass.

Use the harness's authoritative model configuration or runtime metadata. A portable
role name is not a model identifier. Do not claim that a prose instruction changes
the running model. Ask for a model mapping only when necessary to proceed; otherwise
disclose use of the current session. Never make paid probe calls to discover models.

If native skills are unavailable, read the matching bundled guideline and announce
it as a guideline. Respect user-only invocation metadata on installed skills.
Capabilities, discovery paths, and permissions must be verified separately for each
harness. This distribution ships no verified native adapter for other products.
